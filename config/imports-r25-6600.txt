# imports-r25-6600.txt - round-25 bring-up rebinds for the 6600 boot frontier
#
# Superset of imports-r24-6600.txt: 26 round-21/23/24 entries plus the four
# process-construction repairs at the end (30 overrides total).
#
# Syntax: <slot-va> <target-va|zero>
#
# A flat runtime image already binds every real export: the slot *is* the
# exporting image's export-table entry.  The 6600 kernel, however, was linked
# against EUser .def revisions whose ordinal order differs from the EUser DLL
# in the same ROM.  The mismatch is not a constant shift: it is 0 at a few low
# ordinals, 3 around the time cluster, and 4 in parts of the descriptor
# cluster.  Every entry below was therefore identified from the *call site*
# (argument registers, object layout, and the function the caller actually
# needs), not by adding a fixed offset.
#
# Round 21/23 entries are repeated so one NK_IMPORTMAP reproduces the whole
# boot.  These are explicit bring-up rebinds, not recovered ROM state.

# ELocl.dll export-table hole (ordinal 20): locale init calls it
# unconditionally.  Bind it to the high-vector zero-return stub.

# --- round 24: system-time cluster ---------------------------------------
# The kernel's P::InitSystemTime path.  Slot 0x503b50c0 is called as
# TInt64::operator>>(int) (hidden return pointer r0, this r1, shift r2); the
# ROM slot held __truncdfsf2, so the pointer was treated as a double and
# underflowed into User::RaiseException (USER-EXEC 3).  The rest of the
# cluster is the TInt64/TTime arithmetic that formats the initial time.
0x503b50c0 0x50389fc8   # TInt64::operator>>(int)
0x503b4980 0x5038cae8   # TTrap::Trap(int&)
0x503b4d1c 0x50389a40   # TInt64::TInt64(int)
0x503b4ffc 0x50389f0c   # TInt64::operator*(TInt64 const&)
0x503b4ec4 0x503a4f84   # TTime::operator+=(TTimeIntervalMicroSeconds)
0x503b46bc 0x503a4380   # TTime::SecondsFrom
0x503b426c 0x503a4344   # TTime::MicroSecondsFrom
0x503b4e50 0x50389ae8   # TInt64::operator/=(TInt64 const&)
0x503b4ecc 0x50389a68   # TInt64::operator+=(TInt64 const&)
0x503b4e58 0x50389e20   # TInt64::operator<<=(int)

# --- round 25: initial thread trap/cleanup state + descriptor Copy --------
# 0x5032b4d0 builds a TBuf<0x80> from the process path, then calls
# 0x503368c4 (TBufBase16(src,len)) and this slot with (dest, src).  The kernel
# expects TDes16::Copy(const TDesC16&), but EUser export index 717 is
# HBufC16::NewLC(int): it treats the destination pointer as a length and
# raises ETDes16MaxLengthNegative (USER 18).  ROM index 247 is the real
# TDes16::Copy(TDesC16 const&) at 0x50388408.
0x503b42c8 0x50388408

# 0x5032b520/0x5032b534: initial process creation looks up an object by name
# in a CObjectCon.  The call passes (CObjectCon*, TInt& findHandle,
# const TDesC16& match, TBuf<128>& name) and constructs the TBuf with max
# 0x80, so it is CObjectCon::FindByName, not FindByFullName (TBuf<256>).
# EUser export index 421 is a TDes16 format helper; the real pair sits at
# 0x50385650 (FindByName) / 0x50385754 (FindByFullName).
0x503b3e28 0x50385650

# EUser export index 2 is a three-descriptor parser, but the kernel's low
# ordinal 2 is the allocator used by DProcess::New (0x5031750c: r0=0xdc).
# The parser returned 0, so the initial process pointer stayed null and
# 0x5032b7c8 dereferenced a null vtable.  User::Alloc is the real
# size-in-r0 allocator and reaches the harness RHeap::Alloc hook.
0x503b379c 0x503988f0

# DProcess's base constructor (0x5032b54c) builds an 8-byte TBuf8 at
# +0x44 with (this, maxLength=8).  EUser index 1302 is an unrelated
# 20-byte object constructor, so the later name copy left with
# ETDes8Overflow (USER 23).  The real TBufBase8(int) is 0x50388b24.
0x503b4bec 0x50388b24
